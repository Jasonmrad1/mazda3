# Private sign-in and Gemini setup

The frontend never receives a Gemini key. An authenticated Supabase Edge Function verifies the session, checks administrator membership, applies per-account usage limits, and calls Gemini. The publishable Supabase key is still public by design; it cannot read another account's data or administer the project.

## Accounts

1. Run `supabase/migrations/202611070004_private_assistant.sql` after migrations 001–003.
2. In Supabase Dashboard → Authentication → Sign In / Providers, disable new public user sign-ups. The `enable_signup = false` entry in `supabase/config.toml` configures local development; it does **not** automatically change the hosted dashboard setting.
3. In Authentication → Users, manually create the user's email and password and confirm the email.
4. Existing confirmed users are granted membership by migration 004. Users created afterward need this administrator SQL, using their real Auth user UUID:

```sql
insert into public.garage_members(user_id)
values ('REPLACE_WITH_AUTH_USER_UUID')
on conflict(user_id) do update set active=true;
```

To revoke online access, set `active=false` on the membership row. Cached local records remain accessible offline on a previously signed-in device until sign-out; this is offline access, not encrypted storage. Signing out hides the account cache and preserves pending records for that account's next sign-in.

## Server secrets and deployment

In Supabase Dashboard → Edge Functions → Secrets, add:

- `GEMINI_API_KEY`: your private Google AI Studio Gemini key. Never paste it into the app, chat, a VITE variable, or source control.
- `GEMINI_MODEL`: optional. Defaults to `gemini-3.8-flash` with automatic fallback through `gemini-3.7-flash`, `gemini-3.6-flash`, `gemini-3.5-flash`, `gemini-2.5-flash`, and `gemini-2.5-flash-lite`. A lower model in this list can be used as the starting point. Other model names are rejected.
- `APP_ORIGIN`: `https://my-garage-mazda-bp.nicecrab11.chatgpt.site`

Supabase provides `SUPABASE_URL` and the server's public/anon client key. The function does not use a service-role key. Set the dashboard switch **Verify JWT with legacy secret** to **OFF**. The handler independently verifies each user bearer token with `auth.getUser(token)` and then checks membership. This supports current asymmetric Supabase session tokens. The publishable key alone is rejected by the handler.

### Deploy from the Supabase website (recommended for your setup)

1. Open your project → Edge Functions → Deploy a new function → Via Editor.
2. Set the function name to exactly `garage-assistant`.
3. Open `supabase/dashboard/garage-assistant.ts`, copy the entire generated file, and paste it into the dashboard's `index.ts` editor in place of its example.
4. Set **Verify JWT with legacy secret** to **OFF**, save, and deploy the function.
5. Add `GEMINI_API_KEY` under Edge Functions → Secrets. It is the only required new secret; the model order and production origin already have defaults.
6. Sign into My Garage and open Assistant. Its header changes from setup pending to ready after the authenticated readiness check succeeds. Generated answers show the model actually used.

The single-file version is regenerated by `npm run build` or `node scripts/build-assistant-function.mjs`. Edit the three source files under `supabase/functions/garage-assistant/`, rather than editing the generated dashboard file.

### Optional CLI deployment

You can also deploy from `C:\CS\Mazda\my-garage` after logging the Supabase CLI into your account:

```powershell
npx supabase login
npx supabase functions deploy garage-assistant --project-ref trrdhmbkyaivlfbuupbf
```

The CLI login is unnecessary when deploying through the website. The browser publishable key cannot deploy functions through either route.

### Free-tier behavior

The default list uses Flash models documented with a free tier in Google's pricing guide, checked 2026-11-07: https://ai.google.dev/gemini-api/docs/pricing . Actual availability, quota, and billing belong to your Google project. Use a Google AI Studio project on the Free tier if you want free-only usage. The Gemini API has no client parameter that forces paid-tier projects to be free. No Google Search/Maps tools or paid-only model names are added by this app. Google's free-tier data-use terms still apply to submitted records.

Fallback occurs on model access/unavailability, quota exhaustion, temporary server errors, and network timeouts within a bounded request deadline. Bad authentication and malformed requests stop immediately. A successful safety-blocked response is not retried on a different model. If all eligible models fail, the user gets an availability error instead of a fabricated answer.

## What Gemini receives

The current local vehicle profile, confirmed and approximate odometer values labelled separately, readings, service/expense history, fuel entries and measured economy, tire measurements, reminders, current maintenance deadlines with their reasons/references, document titles/page counts, up to eight retrieved source passages, and the last twelve conversation messages. Pending local changes are included. VINs, photos, binary PDF contents, attachments, passwords, and API keys are excluded.

Each record list is capped at 1000 entries and the request is capped at 350 KB; counts disclose any truncation. Source retrieval searches uploaded manual text by subject and returns matching passages with document and page IDs. Navigation manuals are excluded as mechanical evidence. It does not claim to browse the web or have access to manuals the user hasn't added.

Gemini is optional. Offline, the handbook and explicitly labelled reference lookup work locally. Online, a missing function or secret produces a setup-pending status and clear error, rather than presenting a local template as an AI answer. Urgent warning symptoms receive immediate safe-action guidance without waiting for a model response.

The function permits eight AI requests per minute and 150 per day per member. The model has no vehicle-control tools and cannot modify app records. Answers are advisory and cite the supplied source IDs; the model can still make mistakes.
